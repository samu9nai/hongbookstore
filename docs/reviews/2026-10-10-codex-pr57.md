## 다음 전환에서 그대로 일반화하지 않을 부분

아래는 병합 차단 지적이나 새로 발견한 런타임 결함이 아니다.

- **오류 타입 단언:** `err as AxiosError<ApiResponse>`는 catch 값이 AxiosError인지 검사하지 않는다. 이 try에는 axios 호출 외에 localStorage 쓰기도 있다. 현재 변경은 기존 오류 접근식을 그대로 유지하므로 신규 회귀로 판정하지 않는다. 다음 기능에서 오류 처리를 새로 작성할 때는 `axios.isAxiosError<ApiResponse>(err)`로 분기하는 방식을 검토한다. 제네릭만으로 서버 JSON의 실제 구조까지 검증되지는 않는다.
- **styled props:** 기존 `status`를 `$status`로 바꾸면 DOM 출력도 달라진다. 이번 동작 보존 전환에서 이름을 유지한 것은 타당하다. 이를 새 컴포넌트에서도 스타일 전용 props를 DOM으로 전달해야 한다는 규칙으로 확대하지 않는다.
- **응답 타입의 범위:** `ApiResponse<LoginTokens>`는 이 axios 호출의 성공 응답에 맞는다. 실패 응답은 data=null이므로 이 타입을 모든 HTTP 응답을 표현하는 계약으로 복제하지 않는다. 오류 data를 읽는 기능은 해당 실패 계약을 별도로 확인해야 한다.

## 실행하지 않은 검증과 남은 위험

- 실제 OAuth 제공자·백엔드·MySQL·Redis를 연결한 로그인, 토큰 재발급과 재학생 인증 왕복은 실행하지 않았다. 이번 리뷰는 소스 대조와 프론트 검사 범위로 진행했다.
- 인증 성공·실패·토큰 누락의 개별 브라우저 시나리오와 언어 전환 조작은 실행하지 않았다. 추가 수동 조작용 Playwright CLI 준비 명령이 응답 없이 대기하여 중단했다. 기존 e2e 통과와 별개다.
- 로컬 Gradle 테스트는 실행하지 않았다. 백엔드 변경이 없으며 원격 백엔드 CI 결과만 확인했다.
- 개발 서버 모드 e2e와 배포 환경 검증은 실행하지 않았다. 브라우저 결과는 로컬 프로덕션 빌드의 preview 기준이다.
- 큰 JS 청크와 stompjs의 net 외부화 경고는 남아 있다. 기존 보안·인증 백로그를 이번 타입 전환이 해결한 것으로 보지 않는다.
- 기존 단위 테스트 7개는 auth 전용 회귀 테스트가 아니다. 이번 동작 보존 판단은 소스 확인과 전후 번들 비교도 함께 근거로 삼았다.
