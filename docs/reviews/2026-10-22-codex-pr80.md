## 기존 문서 오류 참고사항

`docs/backlog.md:101`은 CommonCard의 `Card`와 `CardHeader`를 모두 index에서 가져올 수 없다고 설명한다. 실제로 `frontend/src/shared/ui/index.ts:14`는 `export * from './CommonCard'`를 선언하고, `CommonCard.ts:43`은 `CardHeader`를 내보낸다. 따라서 CardHeader에 관한 설명은 틀리다. 같은 이름의 명시적 export가 있는 `Card`와 구분해야 한다.

근거 수준은 **소스 확인**이다. 기준 커밋 `6cb28fb`의 FE-13에도 같은 문구가 있어 PR 신규 결함이나 병합 차단 항목으로 계산하지 않았다. FE-13을 정리할 때 CardHeader를 해당 설명에서 빼면 된다. 이번 리뷰에서는 원문을 수정하지 않았다.

## 수동 확인과 원격 CI

- 주 리뷰어가 완료 항목 20개의 요약과 리뷰 목차 8개의 판정을 원문에 대조했다. BE-03의 Content-Type·실제 알림 검증 제안과 OPS-11의 버전 덮어쓰기 제거 조건도 PR #78 리뷰의 제안과 맞는다.
- 독립 리뷰어가 백로그의 파일·줄 주변 소스를 확인했다. 주 리뷰어도 CardHeader export, App 라우트, TypeScript 설정과 주요 요청 흐름을 확인했다.
- 리뷰 HEAD에 연결된 [CI 실행 39794253449](https://github.com/samu9nai/hongbookstore/actions/runs/39794253449)은 마지막 조회에서 `queued`였다. 백엔드 테스트·프론트엔드 검사·프론트엔드 e2e 세 job도 조회 시 모두 `queued`였고 conclusion은 없었다. **원격 CI 성공을 확인하지 못했다.**

## 실행하지 않은 검증과 이유

- GitHub 브라우저에서 링크 클릭과 앵커 이동은 실행하지 않았다. 로컬 검사는 GitHub의 slug 생성 규칙을 근사하므로 실제 렌더링 검증과 구분한다.
- 로컬 앱 단위 테스트·타입 검사·빌드·e2e·백엔드 통합 테스트·DB 검증은 다시 실행하지 않았다. 이번 PR은 Markdown만 바꾸며 API·설정·의존성·실행 코드를 바꾸지 않는다.
- 메인 JS 청크 약 1,038 kB는 재빌드로 재측정하지 않았다. 배포·외부 toxic-filter 실행·모델 품질도 확인하지 않았다.
- 완료 항목의 과거 취약점 수를 OSV로 다시 조회하지 않았다. 이번 검토에서는 요약이 이전 기록의 결론을 유지하는지 확인했다. 과거의 0건을 현재 보안 상태의 검증으로 해석하지 않는다.

## 리뷰어의 변경과 후속 작업

리뷰어는 이 문서와 `docs/reviews/README.md`의 목차 한 줄만 추가했다. 애플리케이션 코드·정책·백로그 상태는 바꾸지 않았다. 새 결함을 등록하지 않았고 커밋·push·GitHub 리뷰 게시·병합은 실행하지 않았다.

병합 전에 CI 완료 결과를 확인해야 한다. 남은 참고사항은 기존 FE-13의 CardHeader 설명이며, toxic-filter 개편 자체는 MOD-06에서 진행한다.
