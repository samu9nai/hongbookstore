일부 Gradle 호출은 처음에 사용자 캐시의 wrapper 잠금 파일에 접근하지 못해 테스트 시작 전에 실패했다. 필요한 권한으로 재실행한 결과를 위 표에 적었다. 이 환경 오류를 저장소 모드의 의도된 실패와 구분했다. 컴파일에서는 변경하지 않은 엔티티의 Lombok 초기값 경고 3개와 기존 deprecated/unchecked 경고가 나왔다.

모듈 집계에 사용한 임시 Gradle init script의 핵심은 다음과 같다. 두 커밋에 같은 스크립트를 적용했다.

```groovy
allprojects {
    plugins.withId('java') {
        tasks.register('reviewRuntimeCoordinates') {
            doLast {
                def coords = configurations.runtimeClasspath.resolvedConfiguration.resolvedArtifacts
                    .collect { it.moduleVersion.id.toString() }.unique().sort()
                file(findProperty('reviewOutput')).text = coords.join('\n') + '\n'
                println "REVIEW_RUNTIME_COORDINATES=" + coords.size()
            }
        }
    }
}
```

실행 형태는 `./gradlew reviewRuntimeCoordinates --init-script /tmp/runtime-review.gradle -PreviewOutput=/tmp/runtime-coordinates.txt --no-daemon --console=plain`이다. 각 실행의 출력 경로는 다르게 지정했다.

## 통합 검증과 기존 결함

임시 `@SpringBootTest`·`@AutoConfigureMockMvc` 테스트는 실제 `LocalStorageUtil` 빈을 사용했다. 저장 경로만 임시 디렉터리로 바꾸고 기본 local 모드·공개 URL 설정을 유지했다. PNG 파일을 세 업무 디렉터리에 저장한 뒤 파일 바이트, 반환 URL, `GET /uploads/...`의 200 응답·`image/png`·본문 일치를 확인했다. `deleteImage` 뒤 실제 파일이 사라지는 것도 확인했다. 별도 loopback HTTP 서버는 외부 프로필 이미지 다운로드를 대신했으며 테스트 종료 시 중단했다.

첫 검사는 삭제 후 같은 URL에 404를 기대했으나 **4개 모두 500으로 실패**했다. 같은 검사를 기준 `11c8b6e`에서도 실행했고 같은 4개 실패를 확인했다. 양쪽에서 파일 저장·정상 조회·삭제까지는 통과했다. `NoResourceFoundException`을 `common/exception/GlobalExceptionHandler.java:115-117`의 포괄 처리기가 500으로 바꾼다. 이 파일과 로컬 리소스 설정은 PR에서 바뀌지 않았다.

이 결과는 기존 결함 **BE-04(P3)**로 남겼다. 이후에는 삭제 후 HTTP 상태 검사를 분리하고, 요청 범위인 저장·조회·파일 삭제·URL 다운로드 검사 4개를 HEAD에서 다시 실행해 통과를 확인했다. 기존 500 응답을 고치거나 404 검사가 통과했다고 보고하지 않는다.
