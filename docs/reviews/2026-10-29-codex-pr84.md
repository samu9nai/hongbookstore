## P3 문서 보완 — BE-03의 테스트 현황 갱신

**위치:** `docs/backlog.md:118` (`c824af2`). **근거 수준:** 소스 확인·실행 확인.

BE-03은 백엔드 테스트가 `contextLoads` 1개와 `ApiContractTest` 6개뿐이며 권한 검사 테스트가 없다고 적는다. 이번 PR은 채팅 REST 권한 테스트 5개를 추가하고 `AGENTS.md:44`의 기준선도 12개로 바꿨다. 따라서 두 문서의 현재 상태 설명이 충돌한다. BE-03의 문장은 변경 전부터 있었지만, 이번 테스트 추가로 설명이 낡았다.

BE-03을 닫을 정도로 전체 서비스·권한 검증이 충분해진 것은 아니다. 해당 설명을 “기존 API 계약 테스트 7개에 채팅 REST 권한 검사 5개를 추가했다. 다른 서비스 로직과 권한 경로의 테스트는 부족하다”로 좁히고, 기존 Content-Type·실제 SSE 페이로드 보완 제안은 유지하면 된다. 실행 코드의 결함이나 병합 차단 항목으로 계산하지 않았다. 기존 BE-03의 설명 보완이므로 새 백로그 ID는 만들지 않았다.

임시 검사는 저장소 밖의 `/tmp/hongbookstore-pr84-review.Wh7uQ9/src/com/hongik/books/Pr84ReviewProbeTest.java`에 두고 Gradle init script로 테스트 소스에 추가했다. 기존 소스와 테스트 파일은 수정하지 않았다. 추가한 검사는 다음 다섯 가지다.

1. H2에 실제 메시지를 저장하고 영속성 컨텍스트를 비운 뒤 구매자·판매자가 JSON 본문과 ID들을 받는다.
2. 비참가자의 방·메시지 조회가 403 및 `ApiResponse` 실패 본문을 반환한다.
3. `buyerId` 없는 요청이 신규 방을 저장하며 구매자·판매자와 `userAId`·`userBId`가 일치한다. 재요청은 같은 방을 반환하고 행을 추가하지 않는다.
4. 없는 방의 두 조회 경로가 400 및 문서에 적힌 실패 본문을 반환한다.
5. Bearer 토큰 없는 세 REST 경로가 기존 인증 계약대로 302와 로그인 Location을 반환한다.

최초 Gradle 실행은 샌드박스의 캐시 잠금 파일 쓰기 제한으로, 최초 e2e 실행은 로컬 포트 바인딩 제한으로 시작하지 못했다. 실행 권한을 확장해 재시도한 결과를 위 표에 적었다. 시작하지 못한 시도를 테스트 실패나 검증 성공으로 계산하지 않았다.

## 수동 확인·통합 범위와 원격 CI

- 주 리뷰어와 독립 리뷰어가 컨트롤러, 엔티티, 인증 필터, 예외 처리기와 프론트 호출자를 소스로 대조했다. 권한 검사보다 먼저 메시지 이력을 읽는 경로나 요청의 구매자 ID를 신원으로 쓰는 경로는 이번 변경에서 찾지 못했다.
- MockMvc 검사는 실제 Spring 인증 필터·컨트롤러·JPA·H2를 사용했다. Redis 블랙리스트 저장소는 목이며 실제 Redis 연동을 검증한 것은 아니다.
- [CI 실행 40718907061](https://github.com/samu9nai/hongbookstore/actions/runs/40718907061)은 리뷰 HEAD에 연결된 실행이다. GitHub API로 `completed/success`와 백엔드 테스트·프론트엔드 검사·프론트엔드 e2e 세 job의 `success`를 직접 확인했다. 이 원격 결과는 로컬 검사 결과와 별개다.

## 실행하지 않은 검증과 이유

- 실제 MySQL·Redis·OAuth 로그인을 연결한 브라우저 채팅 시작·입장·메시지 이력 조회는 실행하지 않았다. 이번 리뷰는 test 프로필의 H2·MockMvc와 백엔드 없는 브라우저 스모크로 검증했으며 해당 통합 환경은 구성하지 않았다.
- STOMP 연결·SEND·SUBSCRIBE와 SSE 전달은 실행하지 않았다. Issue #83이 REST 3개 API만 대상으로 정했고 실시간 채널은 기존 SEC-04·SEC-03 후속 작업이다.
- 수정 전 코드에서 재현 테스트 4개가 실패했다는 PR 작성자의 기록은 다시 실행하지 않았다. 이번 실행 결과는 리뷰 HEAD에 대한 결과다.
- 테스트 클래스의 무작위 순서는 다시 실행하지 않았다. 전체 기본 실행과, 이전 격리 문제가 났다고 PR이 기록한 클래스 이름 순서를 확인했다.
- 배포 환경과 동시 요청의 중복 채팅방 생성은 검증하지 않았다. 배포·스키마·방 생성의 중복 방지 로직은 이번 변경 대상이 아니다.

## 남은 위험과 리뷰어의 변경

SEC-04의 STOMP 인증·참가자 검사 누락은 그대로 남는다(`config/WebSocketConfig.java:12-22`, `domain/chat/controller/ChatMessageController.java:69-129`). 이번 REST 수정만으로 실시간 채팅의 접근 통제가 완성됐다고 볼 수 없다. 예약 API 오류 코드는 기존 BE-06에서 처리한다. PR #82를 먼저 병합하면 공통 변경 파일인 `AGENTS.md`와 `docs/backlog.md`를 합치면서 테스트 기준선과 각 항목을 다시 맞춰야 한다.

커밋된 `ChatRoomAccessTest.java:107-117`은 빈 메시지 목록의 200만 확인하고, `:131-138`은 `buyerId` 없는 기존 방 반환을 검사한다. 이번 임시 검증으로 실제 메시지와 신규 생성도 확인했지만 그 두 경로의 상세 단언은 저장소 회귀 테스트에 남지 않는다. 다음 테스트 보완에서 추가할 수 있다.

리뷰어는 이 문서와 `docs/reviews/README.md`의 목차 한 줄만 추가했다. 애플리케이션 코드·커밋된 테스트·정책·백로그 상태를 바꾸지 않았다. 커밋·push·GitHub 리뷰 게시·병합은 실행하지 않았다.
