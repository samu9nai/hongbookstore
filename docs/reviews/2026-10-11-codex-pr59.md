## 타입 전환의 한계

- `MapPlace`는 저장 장소 DTO와 검색 결과를 함께 표현한다. 저장 응답의 id가 항상 숫자이고 address가 필수라는 사실까지 이 타입이 강제하지는 않는다. 현재 사용에 모순은 없지만 정확한 서버 DTO 타입과 동일하다는 설명은 이 범위로 한정한다.
- axios 제네릭과 JSON.parse의 결과 주석은 서버 JSON의 실제 구조를 검사하지 않는다. 정상 응답 계약을 문서화한 것이며 잘못된 응답도 안전하게 처리한다는 증거는 아니다.
- `full as MapPlace`는 null 좌표 가능성을 제거하지 않는다. 다음 전환에서 같은 단언을 복제하는 기준으로 삼지 않는다.
- FE-16은 별도 수정 작업으로 남긴다. 이 PR에서 id를 변환하면 Issue #58의 동작 보존 범위를 벗어난다.

## 원격 CI와 브라우저 검증

[CI 실행 38126583788](https://github.com/samu9nai/hongbookstore/actions/runs/38126583788)의 head_sha가 리뷰 HEAD와 일치하고 실행이 completed/success인 것을 GitHub에서 확인했다. 백엔드 테스트·프론트엔드 검사·프론트엔드 e2e 3개가 통과했다. 로컬 결과와 구분한다.

기존 로컬 e2e는 API 응답을 대체하는 홈·로그인 스모크다. map 회귀 전체를 검증하는 테스트는 아니다. 주 리뷰어는 별도로 임시 HEAD 비압축 빌드의 preview에 Playwright CLI를 연결하여 아래 조작을 확인했다.

1. 가짜 사용자·장소·카테고리 응답과 테스트용 인증 값으로 `/hongikmap`이 열린다.
2. 사이드바 선택 상자에서 카테고리를 고르면 담긴 장소 이름과 주소가 표시된다.
3. 그 장소를 누르면 상세 모달의 이름·주소·설명이 표시된다.
4. 장소 검색 결과의 이름에서 태그가 제거되고 도로명 주소가 표시된다.
5. 검색 결과를 누르면 새 장소 추가 모달의 이름·도로명 주소 입력값이 채워진다.

최종 지도 조작 중 수집한 window error 목록은 0건이었다. 외부 네이버 지도 SDK와 폰트 요청은 차단했다. 콘솔에는 폰트 차단과 JSON으로 대체한 알림 SSE의 MIME 오류가 남았으므로 콘솔 오류 0건으로 보고하지 않는다. 첫 테스트용 인증 값은 JWT 형식에 맞지 않아 로그인으로 이동했다. 형식만 맞춘 가짜 값으로 수정한 뒤 위 조작을 완료했다. 실제 인증 성공을 확인한 검사는 아니다. 검증용 브라우저와 preview 서버는 종료했다.

## 실행하지 않은 검증과 남은 위험

- 실제 백엔드·MySQL·Redis와 연결한 장소 저장, 카테고리 생성·이름 변경·삭제, 장소 담기·빼기 왕복은 실행하지 않았다. 이번 리뷰의 브라우저 검증은 응답을 대체한 환경으로 한정했다.
- 실제 네이버 검색·지도 SDK, 마커 표시, 지도 이동과 길찾기는 검증하지 않았다. 외부 요청을 차단했으며 실제 API 키와 응답을 사용하지 않았다.
- null 좌표 fallback의 실제 지도 동작과 FE-16의 브라우저 재현은 실행하지 않았다. 기존 코드와 현재 코드의 동일성은 소스로 확인했다.
- 로컬 Gradle 테스트는 실행하지 않았다. 백엔드 변경이 없으며 원격 백엔드 CI 결과만 확인했다.
- 개발 서버 모드 e2e와 배포 환경 검증은 실행하지 않았다. 브라우저 검증은 로컬 빌드의 preview 기준이다.
- 큰 JS 청크와 stompjs의 net 외부화 경고가 남는다. 기존 테스트 7개가 MapPage의 전체 회귀를 보장하지는 않는다. 이번 동작 보존 판단은 소스 확인과 전후 번들 비교도 근거로 삼았다.

## 리뷰어의 변경과 후속 작업

리뷰어는 이 문서만 추가했다. 신규 결함을 확인하지 않아 백로그를 추가하거나 정책을 바꾸지 않았다. FE-16과 fallback 단언의 한계는 후속 검토 대상으로 남긴다.
GitHub 댓글·리뷰 게시, 커밋·push·병합은 하지 않았다. 병합은 사용자가 D-I에 따라 merge commit으로 수행한다.
