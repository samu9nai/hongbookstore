# 결정 기록

이 문서는 홍책방의 정책·방향 결정을 기록한다. 에이전트는 **미결정 항목을 임의로 정하지 않는다.**
미결정 항목에 걸리는 작업을 만나면 구현을 멈추고 사용자에게 선택지를 제시한다.

## 기록 방법

- 사용자가 결정하면 항목을 "결정됨"으로 옮기고 날짜·결정·이유를 적는다.
- 결정을 뒤집을 때는 기존 항목을 지우지 않고 "대체됨: D-xx"를 적은 뒤 새 항목을 추가한다.
- 에이전트의 제안은 "제안" 칸에 적는다. 제안은 결정이 아니다.

## 확인이 필요한 제안

에이전트가 기본값으로 적용했지만 사용자의 확인을 받지 않은 항목이다.

| 관련 | 제안 | 이유 |
|---|---|---|
| FE-11 | 새로 만들거나 옮긴 `.ts`·`.tsx` 파일은 `strict` 모드로 검사한다. `allowJs`는 전환이 끝날 때까지 켜 두고 `checkJs`는 끈다 | 처음부터 엄격하게 시작하면 나중에 다시 고칠 일이 없다. JS 파일은 검사하지 않으므로 기존 파일에 영향이 없다 |
| FE-11 | 의존이 적은 모듈부터 옮긴다: `utils`·`lib`·`api` → `contexts`·`styles`·`components/ui` → 나머지 `components` → `pages`(영역별) → `App`·`main`·`i18n`. 마지막에 `allowJs`를 끈다 | 먼저 옮긴 모듈의 타입을 나중 모듈이 그대로 쓴다. 한 PR에는 한 단계만 담는다 |
| FE-11 | 파일을 옮길 때는 동작을 바꾸지 않는다. API 접근 방식 통일(FE-03) 같은 구조 변경은 따로 한다 | 타입 추가와 동작 변경을 섞으면 리뷰와 되돌리기가 어렵다 |
